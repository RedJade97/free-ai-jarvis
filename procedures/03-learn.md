# Learn and retest

Purpose: maintain revisable knowledge from repeated experiments.

1. List every relevant lesson and its original claim. Read stored instruments and results before proposing new claims.
2. Define the eligible observation set before comparing performance. Keep an ID manifest and a reason for every exclusion. Separate platforms, cohorts and post ages.
3. For new hypotheses, identify examples and counterexamples. Record an observable feature and a prospective test rule. A new claim starts as a hunch.
4. Execute the predefined local retest, or reproduce the documented calculation manually. Do not claim execution from reading the prompt. Account for all eligible items; if batching is needed, confirm processed count versus expected count.
5. Inspect individual examples, alternative explanations and leave-one-out sensitivity. State that an observational association is not a proven cause. The source grouping and labels still require human judgment.
6. Preserve the original claim and every supporting, inconclusive or opposing result. Reusing the same evidence cannot add confirmations. Flag lessons needing retest or stale information.
7. Write a weekly report and evidence inventory. End with up to three next-test briefs: property to change, what stays similar, metric, evidence and failure criterion. Create new experiments only for tests the user selects.

Completion evidence: dated results, evidence/exclusion counts, changed lesson statuses, a saved report and selected next tests. A spoken summary is an optional output of this evidence process.
